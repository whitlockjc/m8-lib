# 6.6.x Baseline Inventory

Source: `fixtures/6.6.x/`, copied from `/Volumes/M8Headless`.
Reported creating firmware: **6.6.3C**. The fixture files themselves carry
file-schema versions, not a reliable record of the creating firmware.
An initial 6.6.x schema and parsed-fixture suite are now registered. This
inventory records the earlier baseline observations, not complete support.

## Header And Size

| File kind | Count | File-schema version | File size | 6.5.x baseline comparison |
| --- | ---: | --- | ---: | --- |
| Instrument | 8 | `6.0.2` | 357 bytes each | Same size; header byte `0x0a` differs |
| Scale | 1 | `4.0.1` | 60 bytes | Byte-for-byte identical to `CHROMATIC_DEFAULT.m8n` |
| Song | 1 | `6.6.2` | 112582 bytes | 256 bytes larger |
| Theme | 1 | `1.0.2` | 53 bytes | Byte-for-byte identical |

The Scale is named `CHROMATIC.m8n` in this set because the M8 name limit
prevented `CHROMATIC_DEFAULT`. It is the default Scale baseline.

## Byte Observations

- Seven standalone Instrument files (`NONE`, `WAV`, `MAC`, `SAM`, `FM`, `MID`,
  `EXT`) differ from their 6.5.x counterparts only at header offset `0x0a`.
  Hypersynth additionally changes `0x39` from `0xff` to `0x00`. In the 6.5.x
  schema this is inside `hypersynth.unknown_before_eq` (`0x36..0x4b`). It may
  be related to the new Shape parameter, but a controlled edit is required.
- The 6.6.x Song differs at header offset `0x0a`, in the 128-byte directory
  field (`0x17`, `0x1c..0x88`, `0x8a..0x8d`), and at `0xbd..0xbe`, two bytes
  currently unknown in the 6.5.x Project record. The path changes from
  `/Songs/6_5_X/` to `/Songs/6_6_X/`; bytes after its null terminator differ
  and remain preserved rather than interpreted as padding.
- Song bytes from `0x00bf` through the entire old 6.5.x file end at
  `0x1b6c5` match the 6.5.x baseline exactly. The 256 additional bytes at
  `0x1b6c6..0x1b7c5` are all `0x00` in this default fixture. Their purpose
  and record boundaries are unknown. A 256-byte addition suggests a possible
  per-row structure, but that is an inference, not a verified field.
- The 6.5.x Kaitai entry can structurally parse all 11 baseline files. It
  reports 16 rows in each Instrument table, 256 Song rows, 128 Song Instruments,
  and a 288-byte Song remainder instead of the older 32 bytes. Parsing alone
  neither validates every field nor proves that the 6.5.x layout is semantically
  compatible with 6.6.x.

## Next Evidence

The first three targeted fixtures listed below have now been collected and
analyzed in [6.6.x_TARGETED.md](6.6.x_TARGETED.md). Their original predictions
are retained here to show why they were requested.

1. A Hypersynth fixture changing Shape alone, ideally from its default to a
   distinctly different option, to test whether `0x39` is Shape.
2. A Song fixture selecting ModFX Comb alone, to identify the stored enum value
   and check whether other Effects bytes change.
3. A Song fixture changing bookmark colors/options at the beginning and end
   of the Song row range, compared with a matching bookmark-only baseline, to
   test whether the new 256-byte tail is involved. Record the exact UI states.
4. Controlled edits of fields already mapped in every file kind, including
   standalone versus Song-embedded Instrument and Scale records. Equal default
   bytes are not sufficient to establish ongoing layout compatibility.
5. Investigate `0xbd..0xbe` with a separate controlled Song fixture if these
   bytes continue changing; do not assign them a meaning from this comparison.

The first three targeted tests are complete and their findings are modeled
in `schemas/6.6.x.ksy` and new file-version components. The remaining checks
above are still needed for broader confidence. Keep the 6.5.x components and
fixtures intact.

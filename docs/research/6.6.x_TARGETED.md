# 6.6.x Targeted Fixture Findings

Fixtures were created with M8 firmware **6.6.3C** and compared against the
fresh 6.6.x defaults in `fixtures/6.6.x/`. This is research evidence, not yet
an exhaustive 6.6.x compatibility claim. Offsets below are absolute
file offsets. The source files on the mounted SD card and the copied fixtures
had matching SHA-256 hashes.

## Hypersynth Shape

`instruments/HYP_SHAPE.m8i` has file schema version `6.0.2`. Relative to
`HYP_DEFAULT.m8i`, the name changes and exactly one other byte changes:

| Field | Offset | Default | Modified |
| --- | ---: | ---: | ---: |
| Hypersynth shape | `0x39` | `0x00` | `0x0b` |

This locates the Shape parameter in the standalone Instrument record. The
6.5.x Hypersynth default has `0xff` at this offset, inside a region currently
classified as unknown. Do not backport Shape to 6.5.x based on this fixture.

The supplied 6.6.x UI labels are: `00` SAW, `01` SOFT SAW, `02` DARK SAW,
`03` SQUARE SOFT, `04` TRIANGLE, `05` SINE, `06` SINE 3X, `07` SINE FB,
`08` SINE FOLD, `09` SINE RING, `0A` SINE HALF, `0B` SINE ORGAN. This fixture
directly verifies the stored values `00` and `0B`; the intermediate labels
come from the user's UI enumeration.

## ModFX Comb

`songs/MODFX_COMB.m8s` has Song file schema version `6.6.2`. Apart from the
directory/save-state bytes and the project name, one Song data byte changes:

| Field | Offset | Default | Modified |
| --- | ---: | ---: | ---: |
| ModFX type | `0x1a5da` | `0x00` | `0x03` |

This is the ModFX type location already mapped in 6.5.x, where `00` is
CHORUS. The controlled fixture establishes `03` as COMB for 6.6.x. It does
not by itself prove every other Effects field is unchanged.

## Bookmarks

`songs/BOOKMARKS.m8s` has Song file schema version `6.6.2`. The chain-cell
bookmark bytes are unchanged in layout from the known 6.5.x bitmask field:

| Row | Offset | Track mask | Selected tracks |
| --- | ---: | ---: | --- |
| `00` | `0x1a97e` | `0x55` | 1, 3, 5, 7 |
| `01` | `0x1a97f` | `0xaa` | 2, 4, 6, 8 |
| `fe` | `0x1aa7c` | `0x55` | 1, 3, 5, 7 |
| `ff` | `0x1aa7d` | `0xaa` | 2, 4, 6, 8 |

The 256-byte region newly appended to the 6.6.x Song begins at `0x1b6c6`.
The selected row-color values are at `0x1b6c6 + row index`; all unselected
entries remain zero in this fixture.

| Row | UI selection | Stored byte |
| --- | --- | ---: |
| `01` | TEXT:TITLES | `0x05` |
| `02` | PLAY MARKERS | `0x06` |
| `03` | CURSOR | `0x07` |
| `04` | SELECTION | `0x08` |
| `05` | SCOPE/SLIDER | `0x09` |
| `06` | METER LOW | `0x0a` |
| `07` | METER MID | `0x0b` |
| `08` | METER PEAK | `0x0c` |
| `09` | TEXT:VALUE | `0x04` |
| `0a` | TEXT:DEFAULT | `0x03` |
| `0b` | TEXT:INFO | `0x02` |
| `0c` | TEXT:EMPTY | `0x01` |
| `f3` | TEXT:TITLES >< | `0x15` |
| `f4` | PLAY MARKER >< | `0x16` |
| `f5` | CURSOR >< | `0x17` |
| `f6` | SELECTION >< | `0x18` |
| `f7` | SCOPE/SLIDER >< | `0x19` |
| `f8` | METER LOW >< | `0x1a` |
| `f9` | METER MID >< | `0x1b` |
| `fa` | METER PEAK >< | `0x1c` |
| `fb` | TEXT:VALUE >< | `0x14` |
| `fc` | TEXT:DEFAULT >< | `0x13` |
| `fd` | TEXT:INFO >< | `0x12` |
| `fe` | TEXT:EMPTY >< | `0x11` |

These samples support a base color code `0x01..0x0c`, an arrow variant
`base + 0x10`, and `0x00` for the unselected/default row state. The meaning
of the other possible byte values has not been tested. The chain bitmask and
row color are independent regions, so a row can carry both kinds of bookmark.

## Unrelated Changed Bytes

Both modified Songs also change their project names and bytes within the
128-byte directory field, including bytes after the path terminator. The
Project record's unknown trailing state at `0xbd..0xbe` also changes. These
are not assigned to Shape, ModFX, or bookmarks. As with 6.5.x fixtures, the
directory's post-terminator bytes must be preserved rather than interpreted
as stable zero padding.

## Remaining Work

- The 6.6.2 Song and 6.0.2 Instrument schema components now model these
  findings. Do not modify the 6.5.x components for new fields.
- Repeat targeted edits on embedded Instruments, Scale, and other shared
  structures before asserting full 6.6.x semantic compatibility.
- Investigate `0xbd..0xbe` separately if its meaning is needed.
- The initial 6.6.x parsed-fixture suite and generated `docs/6.6.x.md` now
  cover the supplied evidence. Expand them as new fixtures arrive.
